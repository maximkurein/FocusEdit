# PROMT_MAC — что перенести из Windows-версии на Mac

Этот файл — готовое задание для Claude Code на **Mac**. Скопируйте его целиком в сессию в корне репозитория (или напишите «выполни PROMT_MAC.md»). Он описывает всё, что появилось в Windows-версии (`windows/`, версии 1.0.0 → 1.5.2) и чего ещё нет в macOS-версии (`Sources/FocusEdit/`), а также что написано для Mac вслепую и ещё не собрано.

Связано: [CLAUDE.md](CLAUDE.md) · [CHANGELOG.md](CHANGELOG.md) · [windows/BUILD.md](windows/BUILD.md) · [VIM_GUIDE.md](VIM_GUIDE.md)

**Актуально для версии 1.5.2** (состояние кода на 21.10.2026; статусы ниже проверены по `Sources/FocusEdit/` и истории git, а не по памяти). Версия у Mac и Windows общая; после выполнения задания поднимите её (`bump minor`).

**Итог на сегодня.** На Mac **собрано и проверено** до 1.1.1 включительно (Vim, RTF, шаблоны, библиотека, outline, превью-окно). Всё, что позже, либо **написано вслепую** (без `swift`, на Windows) и требует сборки — это раздел 1, либо **ещё не начато** — это раздел 2. Если на Mac есть незапушенная работа, сверьте её с таблицей статусов в начале раздела 2 и поправьте статусы.

## 0. Как работать

- Сначала прочитайте `CLAUDE.md` и `windows/BUILD.md`. В Windows-версии логика написана на TypeScript и покрыта тестами в `windows/tests/`: используйте её как **эталон поведения** (алгоритмы, тексты сообщений, граничные случаи). Windows-файлы не менять.
- Код — Swift в режиме языка 5, только системные фреймворки (AppKit, WebKit, AVFoundation), macOS 13+. Сторонние зависимости не добавлять.
- Стиль: как в соседнем коде (плотность комментариев, имена). Строки интерфейса — по-английски, как сейчас.
- Все команды — из корня репозитория (относительные пути `./package.sh`, `.build/…` в другом каталоге не работают).
- Быстрый цикл: `swift build && .build/debug/FocusEdit --selftest` (self-test не требует бандла). Для ручной проверки и в конце — `./package.sh --no-dmg`, затем запуск бандла напрямую: `.build/FocusEdit.app/Contents/MacOS/FocusEdit examples/welcome.md` (не через `open` — в лаборатории он запрещён), остановка `pkill -f FocusEdit`. Бинарник в готовый бандл не копировать: ломается подпись, macOS убивает приложение.
- Тесты: новые проверки добавлять в `SelfTest.swift` (`check(name, actual, expected)`), отдельной группой рядом с существующими (`syntax`, `completion`, `editing`, `rtf`, `vim`) — например `markdown`, `palette`, `session`, `links`, `outline`, `live`. Чистую логику выносить в отдельные типы, которые можно проверить без окна.
- Визуальная проверка без экрана: `.build/FocusEdit.app/Contents/MacOS/FocusEdit "$PWD/examples/welcome.md" --snapshot "$TMPDIR/ui.png" [--theme Dark] [--content]` — пригодится для полосы прогресса, превью и живой разметки. Если меняется вид окна, обновите скриншоты README (`docs/images/`, команды в `BUILD.md`).
- RTF открывается как `DocumentKind.markdown` (через `RTFMarkdown`), поэтому всё, что делается для Markdown, работает и в RTF; Fountain — отдельный вид, `plain` без подсветки.
- Если Windows-эталон кажется ошибочным, Windows не правьте: сделайте на Mac правильно и опишите расхождение в итоговом отчёте.
- Версия меняется **только** через `python3 scripts/update_version.py bump minor|patch` (скрипт правит и Windows-файлы; в `package-lock.json` не должно попадать ничего, кроме строк версии: в рабочей копии он может быть изменён локально из-за `npm`, его не коммитить целиком).
- После каждой функции: `swift build`, `--selftest`, ручная проверка, запись в `CHANGELOG.md` (раздел `[Unreleased]`, по-английски, как там принято), правка `README.md`, `START_HERE.md`, подсказок (`HintsViewController`). Новые типы и связи — в раздел «macOS architecture» `CLAUDE.md`; в этом файле отметьте пункт сделанным (колонка «На Mac»).
- Делайте по одной функции за раз, коммитьте отдельно. Пуш только по моей просьбе, в **оба** remote: `git push origin main` (GitHub) и `git push second main` (Forgejo). Если пуш отклонён, сначала `git fetch` и `git rebase origin/main` (на сервере уже случались чужие коммиты в `CLAUDE.md` и `PROMT_MAC.md`).
- Скриптовать правку Swift-файлов через Python/heredoc осторожно: `\n` внутри строкового литерала дважды превращался в настоящий перенос и ломал сборку (последний раз — в `SelfTest.swift` и `FocusTextView.swift` при написании 1.5.0). В тексте с обратными слэшами правьте файлы инструментом Edit/Write, а не heredoc, и перечитывайте результат.

### 2.1. Палитра команд

- **Windows:** `windows/src/palette.ts` (поиск, оверлей), набор команд `allCommands()` в `windows/src/main.ts`. Открывается `Ctrl+Shift+P`.
- **Поиск (`matchScore`):** запрос разбивается на слова, **каждое** должно найтись в «названии + ключевых словах» без учёта регистра. Подстрока: чем раньше, тем лучше, начало слова (после пробела `:` `/` `-` `.`) лучше середины (+20). Иначе буквы по порядку («thdk» → «Theme: Dark») как слабое совпадение (+100). Сортировка по оценке, затем по исходному порядку; пустой запрос — весь список в исходном порядке.
- **Состав команд:** новый документ, открыть, сохранить, сохранить как; экспорт HTML, печать/PDF, копировать как HTML; вид (Edit / Split / Preview); outline; режимы фокуса; typewriter; темы (с ключевыми словами: System — «auto follow», Light — «day white», Dark — «night black», Sepia — «paper warm»); ширина колонки; шрифт; размер текста ±; полный экран; Vim вкл/выкл; форматирование (жирный, курсив, ссылка); цели по словам; подсказки; About; приветствие; **последние файлы** («Open recent: имя», в ключевых словах папка).
- **Число в запросе:** если введено только целое > 0, сверху добавляются «Word goal: N words» и «Go to line N».
- **Mac:** оверлей-панель по центру окна (поле ввода + список, стрелки/Enter/Esc, клик вне панели закрывает, фокус возвращается в текст). Клавиша — **⇧⌘P** (как в Sublime/VS Code). Сейчас ⇧⌘P занят превью: перенесите превью на **⌥⌘P**, проверив, что в меню нет конфликтов. Команды строить из реальных селекторов/состояния меню Modus, View, Format, Library (по возможности брать названия и клавиши из `MenuBuilder`). Логику поиска вынести в чистый тип и покрыть `--selftest` (случаи из `windows/tests/palette-session-links.test.ts`).

### 2.2. Цель по словам, таймер сессии, слова в выделении

- **Windows:** `windows/src/session.ts` (`Session`, `countWords`, `formatDuration`), вывод в `renderStats()` в `main.ts`.
- **Правила:**
  - слово — последовательность непробельных символов (`\S+`);
  - «написано» = слова сейчас − слова на начало сессии (базовая линия ставится при открытии документа и при установке цели), **не меньше нуля**;
  - таймер идёт только пока вы пишете: секунда засчитывается, если с последней правки прошло ≤ 30 с; раз в секунду `tick`; разрыв > 5 с (сон ноутбука) не засчитывается;
  - прогресс = min(1, написано / цель).
- **Вид:** под заголовком окна строка `+написано / цель words · м:сс`, при достижении ` · goal reached`; тонкая (2 pt) полоса прогресса под тулбаром (акцентный цвет, зелёная при 100 %), скрыта, пока цели нет. Пока выделен текст, вместо счётчика — «N words selected» (не считать выделение > 200 000 символов).
- **Mac:** сейчас подзаголовок окна показывает число слов и время чтения. Добавьте то же: цель из палитры («Word goal: 250 / 500 / 1000 / 2000 / off» и число), хранить в `Preferences`. Полоса — тонкий `NSView` под тулбаром либо в `EditorViewController`. Чистую часть (`Session`) покрыть `--selftest` (случаи из тех же тестов).

### 2.3. Режимы просмотра: Edit → Split → Preview

- **Windows:** `setView`/`applyView` в `windows/src/main.ts`; кнопка с глазом. Три режима по кругу: только редактор → редактор + живое превью → только превью (редактор скрыт). `Esc` в режиме «только превью» возвращает к правке.
- **Выход из «только превью»:** курсор ставится на строку, соответствующую месту чтения (доля прокрутки превью × число строк), редактор прокручивается туда по центру. Вход в «только превью» — превью открывается там, где стоял курсор.
- **Mac:** сейчас есть панель рядом с текстом (две ситуации: закрыта/открыта). Добавьте третье состояние «только превью»: `editorItem.isCollapsed = true` с `canCollapse = true`, аккуратно с первым ответчиком (`makeFirstResponder`), и вернуть курсор по тем же правилам. Цикл по ⌥⌘P и кнопке «глаз»; подпись/подсказка кнопки должна показывать текущий режим. Для Fountain превью недоступно (как сейчас).

### 2.4. Полноценный Markdown в превью

- **Windows:** `windows/src/markdown-html.ts` — отрисовка по дереву разбора (CommonMark + GFM) с тестами `windows/tests/markdown-html.test.ts`.
- **Чего нет в `MarkdownToHTML.swift`** (он минимальный): таблицы с выравниванием `:--|:-:|--:`, списки задач `- [x]`, зачёркивание `~~x~~`, вложенные списки, начальный номер нумерованного списка, абзацы с жёсткими переносами (два пробела), setext-заголовки, горизонтальная линия, ссылки через определения `[текст][метка]` + `[метка]: url`, голые URL как ссылки, escape-символы, блоки кода с `class="language-…"`, HTML в документе показывать как текст.
- **Безопасность (обязательно, см. раздел 1):** кавычки в атрибутах экранируются; ссылки только `http`, `https`, `mailto`; для картинок `http`, `https`, `data` и относительные пути; остальное — только текст ссылки.
- **Mac:** улучшайте `MarkdownToHTML.render` (чистая функция, легко проверить в `--selftest` теми же примерами). Полноценный разборщик на Foundation писать не нужно: достаточно блочного разбора построчно + инлайн-регулярных выражений, но с перечисленными случаями. Картинки с локальными путями на Mac можно показывать через `baseURL` папки документа (`loadHTMLString(_, baseURL:)`), если это безопасно при отключённом JavaScript.

### 2.5. Ссылка из вставки

- **Windows:** `windows/src/links.ts` (`linkFromPaste`) + обработчик `paste` в `editor.ts`.
- **Правило:** выделен непустой текст без перевода строки и в буфере ровно один `http(s)`-адрес без пробелов → вместо вставки получается `[текст](адрес)`. В тексте экранируются `[` и `]` (`\[`), в адресе `(` → `%28`, `)` → `%29`. Пробелы по краям выделения остаются **вне** ссылки. Курсор — после ссылки. Для Fountain не действует.
- **Mac:** переопределить `paste(_:)` в `FocusTextView`. Вынести чистую функцию, покрыть `--selftest` (случаи из `windows/tests/palette-session-links.test.ts`).

### 2.6. Приветственный документ при первом запуске

- **Windows:** `windows/src/welcome.ts` (текст, флаг «уже показывали»), показ в `start()` в `main.ts`: только если нечего восстановить, нет файла в командной строке и нет последнего документа; затем флаг ставится всегда. Документ называется `Welcome.md`, без пути (при «Сохранить» откроется диалог «Save As»). Команда палитры «Open the welcome tour» открывает его снова (с вопросом, если есть несохранённые изменения).
- **Mac:** при первом запуске открыть новый документ с текстом на основе `examples/welcome.md` (дополнить: палитра, цели по словам, вставка ссылки, Vim, клавиши Mac). Флаг в `UserDefaults`. Пункт Help ▸ «Welcome tour» для повторного показа. Не показывать, если приложение запущено с файлом или есть восстановленные документы.

### 2.7. Outline: что умеет Windows-версия

- **Windows:** `windows/src/outline.ts` (`extractHeadings`, `activeHeading`), тесты `windows/tests/outline.test.ts`.
- Сверьте `OutlineViewController` с этими правилами и доведите: не считать `#` внутри блоков кода (``` и ~~~, включая пересечение разных ограждений), пропускать YAML-шапку `---…---` в начале файла, setext-заголовки (`===`, `---`), не принимать маркер списка/цитату за заголовок, `#` без пробела/текста — не заголовок; для Fountain — сцены (`INT.`, `EXT.`, `EST.`, `INT./EXT.`, `I/E`) и секции `#`. **Подсвечивать текущий заголовок** (последний на уровне или выше курсора) и обновлять подсветку при движении курсора; при выборе строки — перемещать курсор и прокручивать, возвращая фокус в текст.

### 2.8. Мелочи, которые стоит выровнять

- **Недавние файлы:** в Windows последний документ открывается заново при запуске без файла. На Mac такое поведение по желанию (системный «Open Recent» уже есть); решите, нужно ли оно в стиле macOS (обычно `NSDocument` сам восстанавливает окна — проверьте, включено ли).
- **Печать как PDF:** Windows печатает отрендеренный документ на белом фоне независимо от темы; на Mac проверьте, что печать/PDF не берут тёмную тему.
- **Подсказки (⌘?):** добавьте разделы про палитру, цель по словам, вставку ссылки, режимы просмотра и живую разметку, как в `windows/src/hints.ts` (разделы Commands, View, Files).
- **Перетаскивание файла:** в Windows пока файл над окном, поверх окна показывается пунктирная рамка «Drop a file to open it»; на Mac `FocusTextView.enableFileDropOpening` уже открывает файл, рамку добавьте по желанию (необязательно).
- **Документация:** `README.md` (Shortcuts, What it does), `START_HERE.md` (по-русски), `CHANGELOG.md`.

### 2.9. Живая разметка (скрывать знаки Markdown вдали от курсора)

- **Windows:** `windows/src/live.ts` (`liveItems`), тесты `windows/tests/live.test.ts`; включено по умолчанию, выключатель — команда палитры «Markup».
- **Что скрывается:** `#`-метки заголовка и пробел после них (пока курсор не на строке заголовка); `**`, `*`, `~~`, `` ` `` — пока курсор или выделение не касаются элемента (касание включает границы); у ссылки `[текст](адрес)` — `[` и `](адрес "title")` (или `][метка]`), у картинки — `![` и `](адрес)`, а подпись показывается курсивом приглушённым цветом; у автоссылки `<url>` — `<` и `>`. Не трогать: маркеры списков, `>` цитат, ограждения кода, таблицы, линии, setext-подчёркивания.
- **Размер заголовков** задаётся всегда (не зависит от курсора), иначе строка прыгает: ≈ 1.7×, 1.4×, 1.2× для `#`, `##`, `###`.
- **Mac:** в `FocusTextView` уже есть `SyntaxEngine` с ролями `SyntaxRole` (`MarkdownHighlighter`). Нужны роли «метка форматирования» отдельно от «содержимое» и признак «элемент, которого касается курсор». Скрывать знаки можно атрибутами при рендере (`NSLayoutManager` temporary attributes или `NSTextStorage`: цвет `.clear` + ничтожный шрифт; либо `NSLayoutManagerDelegate.layoutManager(_:shouldGenerateGlyphs:…)` с `.null`-глифами — именно этот вариант не оставляет «дыр» в раскладке). Курсор не должен застревать внутри скрытых знаков (перепроверьте перемещение стрелками, Backspace, выделение). Взаимодействие с фокусом (приглушение), Vim-блочным курсором и typewriter-прокруткой проверить. Выключатель — пункт меню Modus и `Preferences`. Чистую функцию «какие диапазоны скрыть при таком выделении» вынести и покрыть `--selftest` случаями из `windows/tests/live.test.ts`.

### 2.10. Стартовый экран (по желанию, из 1.5.1)

- **Windows:** `updateStart()` в `windows/src/main.ts`, стили `.start*` в `styles.css`. Над пустым несохранённым документом (нет пути, нет правок, нет текста) показывается карточка «Start»: «New file…» (⇧⌘N / Ctrl+Shift+N), «Open…», до пяти последних файлов (имя и папка). Первая набранная буква убирает её; редакторская подсказка «Start writing…» под ней скрыта. Появляется после запуска без файла, после «Close file» и после замены документа пустым.
- **Mac:** у документных приложений при нуле окон обычно ничего нет, поэтому это необязательно. Если делать: небольшое окно-«стартер» (или `NSOpenPanel`-подобное) при `applicationShouldOpenUntitledFile`, когда нет аргумента и нет восстановленных документов, с теми же тремя действиями, списком из `NSDocumentController.shared.recentDocumentURLs` и закрытием при открытии любого документа. Не показывать вместе с приветственным документом (2.6). Решите сами, нужно ли оно в стиле macOS; в отчёте опишите выбор.

## 3. Что в Windows есть, а на Mac уже сделано (сверка, ничего переносить не нужно)

Vim-режим с учебной панелью (общий движок `VimEngine`, тексты пояснений совпадают; сверьте, что случаи из `windows/tests/vim.test.ts` есть в группе `vim` self-test); продолжение списков, автоскобки и серая подсказка (Windows-порт в `editing.ts`/`completion.ts` мог уточнить граничные случаи — прогоните случаи из `editing.test.ts` и `completion.test.ts` через `--selftest`); тема System; недавние файлы (Open Recent); экспорт HTML/PDF и «Copy as HTML»; открытие файла перетаскиванием на окно (`FocusTextView.enableFileDropOpening`); outline; About с версией (нужно только сверить пункт 1). **Общая нумерация версий:** Mac и Windows используют одну версию.

**RTF (с 1.5.0 есть и в Windows).** Эталон здесь — Mac (`RTFMarkdown.swift`), Windows-порт `windows/src/rtf.ts` написан по тем же правилам, но независим. Прогоните случаи из `windows/tests/rtf.test.ts` через группу `rtf` в `--selftest` и опишите расхождения в отчёте. Известные отличия Windows: заголовки 4–6 уровней читаются как жирный абзац (размер 13 pt не отличить от тела); блок кода пишется моноширинными абзацами и читается обратно как ограждение ```; «потери» называются `underline`, `colours`, `images`, `tables`, `fonts`; ссылка с подчёркиванием потерей не считается. Файл, созданный мастером New File… на Mac (`NewFile.data(format: .rtf, …)` → `RTFMarkdown.rtf(fromMarkdown:)`), должен открываться и в Windows-версии, и в TextEdit.

## 4. Порядок и критерии готовности

1. Раздел 1 (проверка уже написанного) — исправить сборку и найденное.
2. По очереди 2.4 → 2.3 → 2.1 → 2.2 → 2.5 → 2.6 → 2.7 → 2.8 → 2.9 → 2.10 (от важного к необязательному; 2.4 и 2.3 — основа превью, на которую опираются остальные; 2.9 — самая трудоёмкая, делать последней).

4. В конце: `python3 scripts/update_version.py bump minor` (проверить `git diff`: в Windows-файлах — только строки версии), `./package.sh`, `./install.sh`, краткий отчёт: что сделано, что не удалось проверить, что отличается от Windows и почему.
